# T12 — Orquestração das execuções privadas

A API autenticada aceita um pedido de comparação com teto confirmado. O servidor confere a aprovação, os limites da entrada, os modelos e o painel. Uma transação registra a execução, a reserva e as tentativas de geração. Cada criação de tentativa aciona uma Function com acesso ao segredo do gateway. Reenviar o mesmo pedido recupera a execução original.

O autor pode consultar cada tentativa assim que ela termina, mesmo com outras ainda na fila. Uma falha preserva as respostas concluídas. Quando há informação suficiente, a Function registra o custo estimado e liquida a parcela da tentativa. A imagem é guardada como objeto e a leitura privada verifica o prazo de retenção. Os juízes ficam registrados na previsão para a etapa de julgamento.

## Evidências

Com o Firestore Emulator, o teste em `functions/executions.test.mjs` verificou:

- Rejeição de usuário sem aprovação, prompt vazio e teto confirmado abaixo da previsão.
- Criação concorrente com a mesma chave, rejeição de reutilização para outro prompt e um único despacho para eventos duplicados.
- Resposta concluída visível enquanto outra aguardava despacho, preservação da geração após falha de outro modelo e liquidação no documento de reserva.
- Leitura de outro usuário e mídia expirada respondendo com HTTP 404.
- Envio dos bytes de imagem ao adaptador de Storage e persistência do tipo de mídia no Firestore.

O Firestore foi exercitado no emulador. As respostas do gateway e a escrita no Storage foram controladas pelo teste. A homologação do gateway real está registrada na [T11](2026-11-25-t11-geracoes.md). O acionamento do gatilho e a leitura do objeto em ambiente publicado fazem parte do aceite integrado.
