# T23 — Custo e acesso das demonstrações

O ensaio usou as duas Functions, contas aprovadas no Firestore Emulator e o gateway real. O cabeçalho de coleta de metadados das demos permitiu conferir cinco eventos em **AI Gateway → Logs**, mantendo a coleta geral desligada. As chamadas pediram a exclusão dos corpos dos logs.

| Chamada              | Entrada / saída na resposta | Tempo na Function | Tempo no gateway | Custo exibido no gateway (USD) | Custo liquidado (USD) |
| -------------------- | --------------------------- | ----------------: | ---------------: | -----------------------------: | --------------------: |
| Cache, primeiro MISS | 52 / 54                     |          1.890 ms |         1.758 ms |                    ~0,00013691 |              0,000137 |
| Cache, segundo MISS  | 52 / 53                     |          1.766 ms |         1.708 ms |                    ~0,00013466 |              0,000135 |
| Fallback, Llama 3.3  | 42 / 50                     |          1.753 ms |         1.424 ms |                   indisponível |              0,000125 |
| Cache, primeiro HIT  | 52 / 53                     |            116 ms |            17 ms |                              0 |                     0 |
| Cache, segundo HIT   | 52 / 53                     |             68 ms |            13 ms |                              0 |                     0 |

O painel identificou ambos os HIT como **Cached Response** e omitiu a contagem de tokens nesses dois eventos. As respostas de cache repetiram o uso da geração armazenada. Os dois MISS custaram US$ 0,000272 ao todo depois do arredondamento por chamada ao próximo microdólar. No fallback, a estimativa usou os tokens e a tarifa do Llama. O painel confirmou o modelo e os tokens, mas omitiu o custo. A duração da Function inclui a viagem até a Cloudflare. Os três registros mensais do ensaio terminaram com reserva zero.

## Acesso e concorrência

A API HTTP rejeitou chamadas anônimas de previsão, confirmação e resultado para ambas as demos. No emulador, contas pendentes e rejeitadas receberam 403. Com saldo suficiente para qualquer uma das demos isoladamente, duas confirmações concorrentes da mesma conta produziram uma reserva e uma rejeição por saldo insuficiente. Reenviar a confirmação vencedora preservou a reserva. Outra conta aprovada recebeu 404 ao consultar o identificador privado. Confirmar um teto adulterado retornou 400 nas duas demos.

A validação completa passou com o Firestore Emulator, incluindo os 113 testes do Vitest, os testes das Functions, build e smoke test.
